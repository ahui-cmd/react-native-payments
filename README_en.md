## Introduction

react-native-payments provides Payment Request-style APIs. This HarmonyOS adaptation uses an RNOH TurboModule to invoke Huawei Payment Kit for basic payment using an `orderStr` generated by the merchant server. 

## Installation

Go to the project directory and execute the following instruction:

**npm**

```bash
npm install @react-native-ohos/react-native-payments
```

**yarn**

```bash
yarn add @react-native-ohos/react-native-payments
```

### Permission Requirements

Before opening the cashier, the host application's bundle name, `app_id`, and `client_id` must match the application in AppGallery Connect, and the network permission must be declared. Signing, the certificate fingerprint, and merchant setup are described in [Instructions](#instructions).

`AppScope/app.json5`:

```json
{
  "app": {
    "bundleName": "same as the AGC application bundle name"
  }
}
```

Add `metadata` and `requestPermissions` under `module` in `entry/src/main/module.json5`. Replace `abilities` with the host application's main ability name:

```json
{
  "module": {
    "metadata": [
      {
        "name": "app_id",
        "value": "APP ID from AGC Project settings > General"
      },
      {
        "name": "client_id",
        "value": "OAuth 2.0 Client ID on the same page"
      }
    ],
    "requestPermissions": [
      {
        "name": "ohos.permission.INTERNET",
        "usedScene": {
          "abilities": [
            "EntryAbility"
          ],
          "when": "always"
        }
      }
    ]
  }
}
```

## Example

The following code shows the basic use scenario of the repository:

> [!WARNING] The name of the imported repository remains unchanged.

```javascript
import * as React from "react";
import { SafeAreaView, ScrollView, Text, TouchableOpacity, View } from "react-native";
import { PaymentRequest } from "react-native-payments";

const orderStr = "";

const buildRequest = () =>
  new PaymentRequest(
    [{ supportedMethods: ["huawei-pay"], data: { orderStr } }],
    { id: "demo-order", total: { label: "总计", amount: { currency: "CNY", value: "1.00" } } },
  );

const Line = ({ name, value }: { name: string; value: unknown }) => (
  <View style={{ marginBottom: 16 }}>
    <Text style={{ textDecorationLine: "underline", fontWeight: "500" }}>{name}</Text>
    <Text>{JSON.stringify(value, null, 2)}</Text>
  </View>
);

export default function PaymentsDemo() {
  const [status, setStatus] = React.useState("");

  React.useEffect(() => {
    buildRequest()
      .canMakePayments()
      .then((available) => setStatus(`canMakePayments: ${available}`))
      .catch((e) => setStatus(`canMakePayments error: ${e?.message ?? e}`));
  }, []);

  const onShow = async () => {
    try {
      const response = await buildRequest().show();
      setStatus(`show() ok: ${JSON.stringify(response)}`);
      await response.complete("unknown");
      setStatus("complete ok");
    } catch (e: any) {
      setStatus(`show error: ${e?.message ?? e}`);
    }
  };

  return (
    <SafeAreaView style={{ flex: 1, backgroundColor: "white" }}>
      <ScrollView contentContainerStyle={{ padding: 16 }}>
        <Line name="orderStr" value={orderStr} />
        <Line name="paymentStatus" value={status} />
        <TouchableOpacity onPress={onShow}>
          <Text style={{ color: "#007AFF", fontWeight: "500" }}>show() initiates payment</Text>
        </TouchableOpacity>
      </ScrollView>
    </SafeAreaView>
  );
}

```

### API

| Name | Type | Parameter Type | Return Value | Required | Platform | OpenHarmony Platform Support | Description |
| --- | --- | --- | --- | --- | --- | --- | --- |
| show | function | / | Promise\<PaymentResponse\> | No | iOS / Android | partially | Opens the cashier with a server `orderStr` and returns a `PaymentResponse` after the user confirms. On success `details.status` is always `submitted` and is not a settlement result. Requesting payer or shipping information rejects with `NotSupportedError` |
| canMakePayments | function | / | Promise\<boolean\> | No | iOS / Android | partially | Checks only the bridge, the `PaymentService` system capability, and that `orderStr` is present. It does not validate the order or whether the user has a card. Requesting payer or shipping information resolves `false` |
| canMakePaymentsUsingNetworks | function | networks | Promise\<boolean\> | No | iOS | No | Static method. Reports whether Apple Pay has a card matching the given networks |
| abort | function | / | Promise\<void\> | No | iOS | No | Dismiss the payment sheet |
| addEventListener | function | eventName, fn | void | No | iOS | No | Register a `shippingaddresschange` or `shippingoptionchange` callback |
| updateWith | function | details | Promise\<void\> | No | iOS | No | Update the current request with new payment details |
| complete | function | paymentStatus | Promise\<void\> | No | iOS / Android | Yes | Finish this response with `success`, `fail`, or `unknown` |

## Other

`paymentResponse.complete` matches Android: the payment sheet dismisses itself, so the call can be omitted. When you do call it, pass one of `success`, `fail`, or `unknown` as `paymentStatus`.
